# Admin report editing
Implement admin-only editing on the report detail page, preserving the existing moderation and authorization boundaries.
The accepted scope is report content and operational fields; author identity and creation metadata are not editable.

## Specs

1. **S1 — Edit report fields and usable detail editor.** User request: “La idea es que el rod admim, desde panel de admin, pueda editar todo lo que sea de algun reporte, osea nombre foto, descripcion etc, actualmente puede el estado me parece y borrarlo, asi que la idea es esa, editar todo el reporte.” Accepted fields: title, description, photo, category, priority, location, and state. Exclude author, creation date, and identifiers. Place the edit flow on the report detail page, available to admins only. User correction: “Cosas para arreglar. Categoria y agua los desplegables, en una sola linea, no uno abajo del otro, Los botones de guardar cambios y de cancelar, no llego a ver ni en pc ni en celular debido q todo lo otro ocupa mucho alto, y rompe. Fijate de agregar scroll o algo sino no entra. Y por otro lado, el tema de latitud y longitud me parece q no va de esa manera, es incomodo, podrias poner un mapa para seleccionar me parece, sino es incomodo tener que buscar latitud y longitud por otro lado me parece..” Keep category and priority selectors on one row, make the dialog body scroll while keeping Save/Cancel visible, and replace manual coordinate inputs with the existing coverage-aware map picker. Latest correction: “SIGO SIN PODER VER LOS BOTONES DE CANCELAR, Y DE GUARDAR CAMBIOS, AHICA TODO LO QUE TENGA ADENTRO POR FAVOR, TANTO EN MOBILE COMO DESKTOP, NO ENTRAN EN EL ALTO DE LA PANTALLA” The dialog must have a viewport-bounded maximum height and one scrollable surface containing the header, all fields/photos, and Cancel/Save actions at the end; users scroll the whole dialog to reach the actions, which must not be fixed outside the scrolling content. Use a wider horizontal two-column layout on desktop and a compact single-column scroll layout on mobile. User selected: “Sí, edición inline”. The repeated modal-specific layout requests are superseded. User then proposed “No es mejor, solo poner un lapiz, y q ahi se vuelva todo editable? en vez de poner muchos lapices por todos lados? que opinas?” and accepted the recommendation with “si”. User clarified: “Al presionar el lapiz, no hace falta q pongas guardar en cada cosa, q se vuelva todo editable y un solo guardar a lo ultimo, lo mismo con el cancelar. se vuelve poco legible, no se entiende”. Provide one admin-only pencil in the report header; activating it puts all mutable fields into inline edit mode, without a modal, with one global Save and Cancel below the comments box; constrain that action box to the comments column width on desktop. Stage photo replacement/removal per image and submit those operations through their existing moderation/authorization workflows; keep the old photo until replacement approval. Show the location picker only in edit mode. Preserve authorization, validation, immutability, and status history/comment behavior. Keep mobile controls legible and tappable.
2. **S2 — Photo replacement and removal.** User choice: “Reemplazar o quitar”; “Sí, conservar hasta aprobar”; “Incluir quitar foto”; and “Cada foto por separado”. Replacement goes through existing moderation and keeps the selected old photo until the new one is approved. Replacing/removing one photo must leave other photos unchanged. Photo removal must use an authorized storage/database path and cannot bypass the existing moderation/storage protections.
3. **S3 — No separate audit trail.** User decision: “no hace falta lo de la auditoria en este caso creo”. Do not add an edit audit log.
4. **S4 — User experience verification.** The updated `AGENTS.md` requires a visible Playwright browser check for UX/UI changes, but the user specified: “Todo esto que vas a leer aca abajo, lo vas a hacer solo si yo te doy permiso, osea luego de hacer algo medianamente grande me preguntas y ahi recien te digo si o no y lo haces, sino no hagas nada porque si(”. Ask for permission after implementation before running the browser verification; if not granted, leave that check pending and report it.
5. **S5 — Pencil placement and visual density.** User feedback: “va bien, pero ubica mejor el lapiz en cada cosa, se ve horrible a nivel estetico,”. The later preference supersedes per-field pencils: use one visually restrained pencil beside the report title/header to enter edit mode, with a usable touch target.
