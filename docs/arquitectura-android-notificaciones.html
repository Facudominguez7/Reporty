App Android y notificaciones push

Cómo la misma aplicación web llega a Android sin código nativo propio, y cómo un evento del servidor termina como notificación en el teléfono.

1. Contexto2. Despliegue3. Capas 4. Suscripción5. Envío6. Datos 7. Estados8. Decisiones9. Archivos

1Diagrama de contexto

El sistema visto como una caja negra: quién lo usa y con qué sistemas externos conversa. La app Android no es un sistema aparte: es una ventana de Chrome sin barra de direcciones que muestra reporty.com.ar.

2Diagrama de despliegue

Un solo repositorio produce dos entregables. La web se despliega en cada merge a main. El paquete Android solo se recompila cuando cambia android/twa/**, porque la app muestra la web publicada: un cambio de la web llega al teléfono sin subir una versión nueva a Play.

Paquete Android

Trusted Web Activity

Generado con Bubblewrap. com.reporty.app, versión 1.0.1 (versionCode 2), minSdk 24, targetSdk 36. Si el teléfono no tiene un navegador compatible, abre una Custom Tab.

Confianza

Digital Asset Links

assetlinks.json declara dos huellas: la de la upload key y la de Play App Signing. Sin las dos, la app muestra la barra de URL.

Firma

Secretos de CI

El entorno google-play de GitHub guarda el keystore, sus claves y la cuenta de servicio con permiso en Play Console.

3Arquitectura en capas

Cada capa solo usa la de abajo. El cliente nunca toca las tablas de push: todo pasa por server actions, que validan la sesión y escriben con el cliente de servicio.

4Secuencia: activar las notificaciones

El permiso del sistema solo se pide después de un toque. En la app Android, Chrome se lo delega a la TWA (DelegationService), y Android 13 o más nuevo muestra su propio diálogo de POST_NOTIFICATIONS.

6Modelo de datos

Dos tablas privadas. RLS activo sin políticas y sin permisos para anon ni authenticated: solo el servidor con service role las lee y escribe. Al borrar la cuenta, la cascada las limpia.

7Estados de un dispositivo

Las push no se pueden prender sin permiso, así que se ofrecen solas. Así decide el aviso automático qué mostrar, por dispositivo y por navegador.

8Decisiones de diseño

Android

TWA y no app nativa

Un solo frontend. Los cambios web llegan a la app sin pasar por Play. El costo: lo que el navegador no permite, la app tampoco.

Push

Web Push estándar

El mismo código sirve para la web, la PWA y la TWA, que recibe las notificaciones de Chrome por delegación. No hay SDK de Firebase en el proyecto.

Librería

WebCrypto

@block65/webcrypto-web-push corre en Cloudflare Workers. web-push se descartó porque depende de crypto y https de Node.

Resiliencia

Mejor esfuerzo

Ninguna función de push lanza errores. La push sale antes del correo, se corta a los 8 s y no requiere que la persona tenga correo.

Mascotas

Sin duplicados

La push de mascota encontrada sale recién cuando el outbox confirma el correo, así un reintento no la repite.

Seguridad

Claves y datos

La clave privada VAPID es un secreto del Worker y nunca va al cliente. La pública se entrega en tiempo de ejecución. Las tablas solo se acceden con service role.

No rotar las claves VAPID sin necesidad: con claves nuevas, todas las suscripciones dejan de funcionar y cada persona tiene que volver a activar las notificaciones.
